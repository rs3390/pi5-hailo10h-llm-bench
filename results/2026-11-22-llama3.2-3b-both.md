# Llama 3.2 3B on both: the CPU (Ollama) and the HAT (hailo-ollama)

Raspberry Pi 5 (8 GB), Hailo runtime 5.1.1, Model Zoo GenAI 5.1.1. 22 November 2026. Medians of three runs after one warm-up; temperature 0, at most 200 tokens. Pi load is the Pi's own processor, as a share of all cores.

Run with an earlier version of `bench.py` that had no "first token, run 1" or "words a second" column. Its third prompt was a long prompt from my own agent (about 420 words), not the one in today's `bench.py`, so that row is not comparable with later runs.

| Where | Model | Prompt | First token (s) | Writing (tok/s) | Tokens | Total (s) | Pi load | HAT held by |
|---|---|---|---|---|---|---|---|---|
| cpu | llama3.2:3b | one line | 0.2 | 6.15 | 8 | 1.5 | 99.8% | hailo-ollama |
| cpu | llama3.2:3b | paragraph | 0.24 | 5.2 | 103 | 20.1 | 99.8% | hailo-ollama |
| cpu | llama3.2:3b | long prompt (agent's own) | 0.24 | 4.85 | 33 | 7.1 | 100.0% | hailo-ollama |
| hat | llama3.2:3b | one line | 1.09 | 2.65 | 18 | 7.9 | 0.6% | hailo-ollama |
| hat | llama3.2:3b | paragraph | 1.08 | 2.66 | 200 | 76.0 | 0.2% | hailo-ollama |
| hat | llama3.2:3b | long prompt (agent's own) | 7.13 | 2.66 | 200 | 82.1 | 0.2% | hailo-ollama |

First runs, from the printed log: CPU one line 0.22 s, paragraph 0.8 s, long prompt 18.32 s. That 18.32 s is unexplained; runs 2 and 3 took 0.24 s and 0.23 s. My guess is memory pressure: my agent kept its own model (Qwen3 4B) loaded beside Llama on 8 GB. I have not checked it.

The same model stopped by itself on the CPU (8, 103 and 33 tokens) and ran to 18, 200 and 200 tokens on the HAT.

"HAT held by" on the CPU rows means hailo-ollama had the chip open while the CPU model ran; it was not doing the work.
